## Gaps
- The engine's own NSE and BSE access cannot be designed around a plain WebFetch call. All three NSE hosts tested through a generic HTTP fetch (www.nseindia.com, its api/quote-equity path, and nsearchives.nseindia.com) timed out, and BSE's API returned 403. This matches PLAN.md §5.5.1's own cookie-bootstrap note and the NSE MCP servers (`nse-bhavcopy`, `cm-market`) named in PLAN.md §1.7; a production run of the engine needs either that cookie bootstrap, the NSE MCP servers, or a headless browser session, never a bare fetch. This lane could not test the NSE MCP servers directly because they were not loaded in this session; P0/engine spikes should confirm them against the same symbol (CIPLA) and report back whether they succeed where this lane's plain fetch did not.
- Could not determine why nsearchives.nseindia.com times out while archives.nseindia.com, a visually similar NSE subdomain, serves the identical kind of file (index CSVs) successfully. Both are officially NSE-operated; the difference may be a CDN/WAF rule scoped by subdomain or by file type (CSV under /content/ versus PDF under /corporate/). This needs a dedicated spike with a CSV-type request to nsearchives (not tested here) to isolate whether the block is path-based or subdomain-based.
- Could not confirm whether SEC EDGAR's apparent lack of a User-Agent complaint reflects WebFetch setting a compliant descriptive User-Agent automatically, or the SEC's rate limiter simply not having triggered yet in a single light request. WebFetch does not expose the outbound request headers it sends, so this lane cannot verify compliance with SEC's stated User-Agent policy (a descriptive string with a contact email) from inside this tool. The engine's own HTTP client must set this header explicitly regardless of what was observed here.
- CRISIL's rating-list page and ICRA's rationale-list page both failed on the specific URLs tried (a 404 and a session-timeout respectively), but a working alternative was not found by this lane within the time available; a dedicated search is needed for each agency's correct public rationale-browsing URL (as opposed to a single rationale PDF reached by search, which did work for CARE).
- GDELT returned HTTP 429 on every attempt in this session, including after a multi-minute gap between the first and second attempt, so this lane cannot confirm GDELT's actual rate-limit window or quota from direct observation; GDELT's own documentation states no API key is required but recommends throttling, which is consistent with what was observed here, but the exact requests-per-minute ceiling remains unconfirmed.
- The RBI reference rate archive's actual historical USD/INR data was not retrieved in this session (only the search-form page, not the postback result), because the download requires a stateful form submission that a single-URL WebFetch cannot replay. The engine will need either a small Selenium/Playwright step or RBI's separate "Database of Indian Economy" (DBIE) portal, which was not tested in this lane, as an alternative static-URL source for the same series.
- niftyindices.com and the two internal NSE paths that failed were tested only for the NIFTY 50 constituent list; the tie-break universe files `ind_niftypharmalist.csv` and `ind_niftyhealthcarelist.csv` (PLAN.md §1.6) were not separately tested in this lane, since they sit on the same niftyindices.com host already confirmed to fail and are expected to behave identically; the engine should fall back to the archives.nseindia.com path for these as well, but that has not been directly confirmed for the pharma/healthcare list variants specifically.
