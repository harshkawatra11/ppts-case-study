Title of the ProjectCustomer ChurnSense AI System Using Machine LearningCustomer churn is a common problem faced by businesses when customers discontinue their services or stop maintaining their relationship with the company. For example, a customer may cancel a subscription or move to a competing service provider.The proposed project, Customer ChurnSense AI System, uses Machine Learning to analyse customer-related information and predict the possibility of customer churn. The system uses factors such as tenure, monthly charges, total charges, contract type and service-related information to identify patterns in customer behaviour.The purpose of the system is to provide an early prediction of whether a customer is likely to leave or continue with the company. This can help businesses take suitable action towards customer retention before the customer actually leaves.B. Statement about the ProblemCustomer churn is a significant concern for businesses that provide subscription-based or continuous services. Industries such as telecommunications, banking, DTH, SaaS and e-commerce can lose considerable revenue when existing customers discontinue their services.A major difficulty is that companies often become aware of customer churn only after the customer has already cancelled the service or switched to another provider. At that point, it becomes difficult to take any preventive action.The main problem addressed by this project is to determine whether historical customer information can be used to predict the likelihood of a customer leaving the company.The system considers information such as customer tenure, monthly charges, contract type and service usage, and uses these attributes to identify patterns associated with customer churn.The central objective is therefore to develop a Machine Learning model that can analyse previous customer data and predict which customers may be more likely to discontinue the service. Such predictions can give businesses an opportunity to take timely measures for customer retention.C. Why the Particular Topic is Chosen? (Present State of the Art)Present State of the ArtCustomer retention has become an important area of concern for modern businesses because maintaining existing customers is essential for long-term business growth. With customers having multiple alternatives available in today's competitive market, businesses need better ways to understand and predict customer behaviour.Machine Learning is increasingly being used for predictive analysis because it can identify patterns from historical data and use those patterns to make predictions.The topic was selected for the following reasons:Customer churn is a practical problem faced by several industries, including telecom, banking and OTT/streaming services.Machine Learning provides a way to predict customer behaviour before the actual churn takes place.Traditional rule-based or statistical approaches may not be sufficient when several customer characteristics need to be considered together. Machine Learning classification algorithms can identify relationships between multiple attributes.Churn prediction is a suitable real-world application of a classification problem and provides an opportunity to implement the complete Machine Learning process.The project allows the application of concepts studied during the course, including data preprocessing, categorical encoding, feature scaling, model training, evaluation and model persistence.Logistic Regression has been selected because it is comparatively simple, interpretable and suitable for classification problems.Therefore, this topic provides a combination of a practical business problem and the application of the Machine Learning concepts studied as part of the course.D. Objective and Scope of the ProjectObjectivesThe main objectives of the project are:To analyse the customer dataset and understand the different factors that may influence customer churn.To identify customer characteristics and patterns that can help in predicting whether a customer is likely to leave or continue with the company.To preprocess the available customer data so that it can be effectively used for Machine Learning.To develop and train a Logistic Regression classification model to predict customer churn, where 1 represents a customer who is likely to churn and 0 represents a customer who is likely to stay.To evaluate the performance of the developed model using accuracy, confusion matrix and classification report.To save the trained Machine Learning model and scaler using pickle, allowing them to be reused for future predictions.To develop a simple real-time prediction module that accepts customer information and provides a prediction of whether the customer is likely to churn or stay.ScopeThe project focuses on a structured customer dataset containing information such as customer ID, gender, age, tenure, monthly charges, total charges, contract type, internet service and churn status.The system treats customer churn as a binary classification problem, where the model predicts:0 – Customer is likely to stay1 – Customer is likely to churnThe project uses supervised Machine Learning to learn patterns from historical customer data and apply them to new customer records.Although the current dataset focuses on customer service-related information, the same approach can be applied to other subscription-based and service-based industries such as telecommunications, banking, OTT platforms, insurance, gyms and SaaS, wherever historical customer data is available.The current scope is limited to analysing the available dataset, developing the Logistic Regression model, evaluating its performance and using the Analysis, Design, Development & Testing Methodology1. AnalysisThe customer churn dataset is first examined to understand its structure and characteristics. Functions such as data.shape and data.info() are used to identify the number of records, columns and data types. data.describe() is used to obtain a statistical summary of the numerical features.2. Design – Data PreprocessingThe dataset is prepared before applying the Machine Learning model through the following steps:Missing Value Treatment: Missing values in numerical columns are replaced with the respective column mean using fillna().Categorical Encoding: Categorical features such as Gender and Contract are converted into numerical values using Label Encoding.Exploratory Data Analysis: A count plot is used to understand the churn distribution, while a correlation heatmap is used to examine relationships between features.Feature and Target Separation: The input features are separated into X, while the target variable, Churn, is stored in y.Train-Test Split: The data is divided into 80% training data and 20% testing data using train_test_split().Feature Scaling: StandardScaler is applied to bring the numerical features to a similar scale.3. Development – Model BuildingA Logistic Regression model is used because the project involves a binary classification problem. The model is simple, interpretable and suitable for predicting whether a customer is likely to churn or stay.The model is trained using:model.fit(x_train, y_train)After training, it can be used to predict the churn status of test and new customer records.4. TestingThe trained model is tested using the unseen test data with model.predict(x_test). Its performance is measured using accuracy score, confusion matrix and classification report, which provides precision, recall, F1-score and support.The trained model and StandardScaler are then saved using pickle so they can be loaded later for real-time predictions.f. Limitations / Constraints of the ProjectThe project has the following limitations:The model is trained on a relatively small, static dataset of approximately 1,000 records, so it may not generalise perfectly to a larger or different customer base.Only Logistic Regression is currently used. Other algorithms may provide better results.The system works with a batch/offline dataset and is not connected to a live company database or CRM system.The available dataset contains a limited number of customer attributes.Label Encoding is used for categorical variables, although One-Hot Encoding may be more appropriate for some nominal categories.J.
